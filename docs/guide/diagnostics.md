# Диагностика компилятора

ArcUX AOT применяет строгий профиль: неизвестное свойство или запрещённый HTML элемент лучше диагностировать при сборке, чем тихо игнорировать.

```bash
python tools/arcuxc.py examples/diagnostics_demo.html \
  -o diagnostics.arcuxi \
  --diagnostic-format=json \
  --max-errors=100
```

Для вывода с исходным контекстом используйте обычный формат сообщений. Поддерживаются:
- категории и коды `AUX-HTML-*`, `AUX-CSS-*`, `AUX-ASSET-*`;
- имя файла, строка, колонка, выделенный фрагмент;
- подсказки об опечатках;
- несколько ошибок за компиляцию и ограничение их количества;
- JSON для IDE и LSP.

## Пример

```css
button {
  widht: 120px;
}
```

Компилятор указывает на `widht` и предлагает `width`. Для запрета JavaScript используются понятные сообщения по `<script>` и `onclick`; рекомендуемая замена — `data-action` и нативный callback.

## IDE

JSON координаты следует переводить из используемой компилятором индексации в нулевые UTF-16 offsets LSP. Unicode normalization, CSS escapes и HTML entities требуют корректной карты между нормализованными токенами и байтами исходника — **полная lossless source map пока не гарантируется**. IDE не должна предполагать, что каждое смещение токена автоматически соответствует одному UTF-16 code unit.
